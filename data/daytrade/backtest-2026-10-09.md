# デイトレプラン バックテスト（実行日 2026-10-09）

仕様 6-2。本人が読んで、パラメータと型の採否を決めるための集計です。**数字は『下の規則を選んだうえでの結果』で、上限・下限の保証ではありません。** パラメータ（ATR係数・帯幅・TPの置き方）は、この結果と2週間以上の前進検証でだけ動かします（仕様 0節・6-3）。

## 条件
- 期間: 計画日 2025-10-08 〜 2026-10-07（完了した日だけ。平日）。設計の回数 783、評価 11197件、有効期限まで足がそろわず除いた版 0、先の版が約定済みで数えなかった版 2
- 設計: 平日の 設計①（NY17:30＝夏06:30/冬07:30、型Aのみ）・設計②（15:30、型A・型B）・設計③（NY8:00＝夏21:00/冬22:00、型A・型B）。毎時の状態更新は案を変えないので再現しない
- 型A・型B × ATR係数（A案=0.5／B案=1.0）。門・型はライブの生成器と同じ関数（`scripts/daytrade/evaluate.js`）で、判定は採点（`daytrade-score.js`）と同じ `fill.js`。H1足の高安だけで判定するため、足の中の順序は分からない
- 入力の再現: 現在値=直前に確定したH1の終値、当日高安=NY17時以降の確定足、日次レベル・ADR20・MTFの向きは日足（`data/mtf`）から PR #11 の計算定義で再計算

### 仮置きの規則（仕様が沈黙している点。decisions.js の Q 番号）
- **Q25** バックテスト：設計3回・再設計の重複計上と追跡の打ち切り → 各設計の案は次の設計時刻まで追跡し、未到達なら取消（未到達として分母に入れる）。Entry帯とSLが同一の再設計は継続とみなし二重に数えない。基準水準・向きが同じ先の版が既に約定していれば、後の版は数えない
- **Q26** バックテスト：約定価格・始値のギャップ・M15確認条件（H1では検証不能） → 約定は最悪Entry。SLの始値ギャップは始値で損切り、TP1は価格で利確。M15確認条件は未反映と明記
- **Q27** バックテスト：過去の設計時点の現在値・当日高安（ADR消化率）の再現 → 現在値=直前に確定したH1の終値。当日高安=NY17時（JST6:00/7:00）以降の確定足
- **Q28** バックテスト：イベント停止（過去のカレンダーが無い） → 全期間『停止なし』（仕様の文言どおり）と明記
- **Q29** バックテスト：軸『ボラ状態』の過去分が無い → 日足（data/mtf）から、risk-feedと同じ定義（ATR14÷終値の過去250営業日パーセンタイル、境界は risk-feed の meta.thresholds）で再計算した近似。見出しに明記
- **Q30** バックテスト：『コスト込み』のコスト、仮想損益の単位 → グロス（コスト0）と、往復コスト=2-2の下限（1.2／1.6pips）を引いた値の2本。主指標はpipsとR。円は1ロット換算の参考列
- **Q31** バックテスト：『エントリー時間帯』『曜日』の基準（未到達の案には約定時刻が無い） → 全指標を設計の回（06:30／15:30／21:00）と設計日の曜日で出す。約定後の指標だけ、約定時刻（JST1時間刻み）の表を別に出す
- **Q32** バックテスト：平均RR・勝率・最大連敗の定義 → 『計画RR平均』と『実現R平均』を別の名前で両方出す。勝率=TP1先着÷約定。最大連敗=集計グループ内を決済時刻順に並べた連続損失。件数(n)を併記、足切りなし
- **Q33** バックテスト：出力の形（軸の掛け合わせ、CSVの中身、ファイル名の日付） → 型×ATR係数ごとに、各軸の値別の周辺集計。CSVは長形式。ファイル名は実行日（JST）
- **Q34** バックテスト：NZDUSD は MTF の日足が無く向きを再計算できない → H1は取得するが案は作らない（ライブと同じ）。mdに明記
- **Q35** バックテスト：取得（timezone=Asia/Tokyo の日付解釈）、CSV先頭行の書式、期間とウォームアップ → timezone=Asia/Tokyo で取得し、h1-bars.json との重なりでOHLCを自己検証。1行目 `# timezone=Asia/Tokyo`、2行目が見出し。窓=完了した365日、取得は窓の3日前から
- ボラ状態の閾値: risk-feed の meta.thresholds.regime_percentile（50／80／95）。日足（data/mtf）のATR14÷終値の過去250営業日パーセンタイルで再計算した近似で、risk-feed の実値ではない
- 到達はH1足の高安がEntry帯と重なった足で判定する。設計時刻・取消時刻をまたぐ足は使わない（次の版も使わない）。帯を飛び越えた足（高安が帯と重ならない）は『未到達』のまま（エントリー側のギャップは約定させない）。月曜の設計①（NY日曜17:30）は直前の1時間の足が無いので再現しない
- 同じ基準水準・同じ向きの先の版が既に約定していれば、後の版は数えない（二重に建てない）。Entry帯またはSLが変わった再設計は、前の版を取消して新しい版として数える（ライブの log.csv と同じ）
- 『pips合計』は銘柄を混ぜると XAUUSD（1pip=0.1ドル）が支配的になる。銘柄の軸で見ること。H1 ATR14 が小さい銘柄（EURUSD・AUDUSD・USDCHF・EURGBP）は、SL幅10pips以上の門を A案（0.5×ATR）がほとんど通らない
- 約定は最悪Entryで成立したとみなす。M15の確認条件（型A）は反映していない。イベント停止はない。9時台・翌1:00以降・土曜0:00以降は新規なし（到達は『失効後到達』に回す）
- コスト込み = 往復で 2-2 の下限（ドル建て・XAUUSD…米ドル決済 1.2pips、その他 1.6pips）を一律に引いた値。`commission_per_lot_jpy`・スプレッドの実数は使っていない（Q30・Q36）
- 『時間切れ』= 有効期限（翌3:00）までSLにもTP1にも届かず、最終足の終値で決済した扱い。勝ちには数えず、勝率の分母には入れる。『同一足』= 同じH1足にSLとTP1の両方が入った件数（SL先着として数えている）。『ギャップ』= SLが始値のギャップで損失が計画より大きくなった件数
- 『取消・未到達』= 次の設計で取消された案のうち到達しなかった件数（到達率の分母に入れている）。同じEntry帯・SLの再設計は継続とみなして二重に数えていない
- NZDUSD は MTF の日足が無く向きを再計算できないため、案を作っていない（ライブと同じ: Q34）
