# デイトレプラン自動生成 実装メモ

仕様：`docs/daytrade-plan-spec.md`（v1.1）。このメモは、実装した範囲・動かし方・**仕様の解釈で迷った点（Q01〜Q44）** を残す。
迷った点は推測で確定せず、「いま実装している暫定の読み」を1か所（`scripts/daytrade/decisions.js` と、それを使う関数）に隔離してある。
本人の回答が出たら、該当箇所だけを差し替え、`decisions.js` の該当項目に `status: "confirmed"` を付ける。
出力（`data/daytrade-plan.txt` / `.json`）の先頭にも、暫定のまま処理している項目の件数と番号を出している。

## 2. 動かし方

```
node scripts/daytrade-plan.js --run=design --slot=2          # 設計（枠 1=NY17:30 / 2=15:30 / 3=NY8:00）
node scripts/daytrade-plan.js --run=status                   # 状態更新
node scripts/daytrade-plan.js --run=design --slot=2 --dry-run --now=<ISO> --data-dir=<dir> --no-risk-feed   # 書き込まない試験
node scripts/daytrade-score.js
node scripts/daytrade-backtest.js [--window-days=365] [--no-fetch]
node --test scripts/daytrade/test/*.test.js
```

## 3. 既存のルールとの差（仕様 9-1 の「差分を列挙するだけでよい」）

| 項目 | 既存（`config/daytrade-rules.json` / `daytrade.js`） | 本仕様の生成器（統合せず別に計算） |
|---|---|---|
| High の窓 | 前15分〜後15分 | 前15分〜後30分 |
| Medium | 警告のみ（停止しない） | High と同じく停止（前15分〜後30分） |
| 指標・中銀の窓 | CPI・NFP 等は前後30分、中銀は前30分〜後60分 | 区別なし（High・Medium は一律） |
| 停止の対象 | 既存の通貨対応・ゲートの状態 | `pair_currencies` の2通貨に該当する High・Medium |
| 停止中の扱い | `gate.state` | 新規のみ禁止（案は残して『停止中』の印を付ける） |
| 鮮度 | `stale_min: 20` | 20分（同じ値。対象は intraday.json・daytrade-context.json・h1-bars.json の `as_of`） |

既存の `gate.state` は「参考：既存ゲート」として、生成時点のスナップショットを表示するだけ（停止判定には使わない）。

## 4. 仕様で迷った点（Q01〜Q44）

影響度：**blocking** = 結果の数字や出力の形が大きく変わるので、本人の回答を待ちたいもの / **material** = 数字が変わるが方向は変わらないもの / **minor** = 表示や細部。
どの項目も、候補を増やさない側・危険側に倒れない側の読みを暫定にしている（鮮度超過のときは発注不可、判断できないものは不採用／未取得／保留）。

## 5. 運用上の注意（実装の外）

- **入力の鮮度（Q14）**：`intraday.yml` は15分ごとの cron を持つが、実際の更新は約2時間おきで、毎時00分の生成時に20分以内なのは1割前後。仕様どおりにすると多くの実行が『発注不可（鮮度超過）』になる。これは生成器の不具合ではなく入力側の更新頻度の問題。`intraday.yml` を変えるのは本PRの範囲外なので、提案としてだけ残す。
- **起動の確実さ（Q22）**：GitHub の `schedule` はこのリポジトリでは大きく欠落・遅延する。外部の定期実行から `workflow_dispatch`（`run=design`＋`slot`、または `run=status`）を呼ぶ方式を推奨。
- **カレンダー（Q23）**：`economic-calendar.json` は当日（JST）分だけ。0:00〜3:00のイベントは、日付が変わった後に `intraday` が更新されてから拾われる。
- **口座の更新**：`data/daytrade/accounts.json` の `equity_jpy` は本人が手で更新する（README に書いてある）。
