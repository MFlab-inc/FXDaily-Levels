# 取引可否の指標（自前の定義） 仕様書

- 版：v1.0（2026-10-30）
- 目的：swing-flow の記事の「全体の取引可否」（swing-flow `SPEC.md` 3-6）に使う5項目（VIX順位・MOVE順位・HY OAS順位・相場の見方の中立の数・イベント警戒）を、GPT への依頼をやめて自前で出せるようにする。**この版では VIX 順位とイベント警戒の2つ**を作り、`data/risk.json` に出す。
- 定義はすべて当方のもの（2026-10-30 ユーザー決定「自前の定義で」）。友人資料の定義の再現ではない。
- 範囲：値・判定の材料・出典を出す。記事の取引可否（stop／reduce／ok）の判定は swing-flow 側（`history.classify_global_status()`）で行い、ここでは行わない。
- GPT の値との照合が済むまでは、フィード（`gpt-feed.*`）に載せない。記事も、照合が済んで切り替えるまでは GPT の値を使う（9節）。

## 1. 用語

| 語 | 意味 |
|---|---|
| VIX | Cboe が公表する VIX 指数（S&P500 のオプション価格から計算する、今後30日の予想変動率）。日次の終値を使う |
| 順位（%） | 過去1年の中で、当日の値がどの位置にあるか（3節） |
| 最重要の予定 | 日米欧英豪加の6つの中央銀行の政策金利の発表と、米雇用統計・米CPI（5節） |
| 基準時刻 | 日本時間のその日の 9:00（記事を作る朝） |

## 2. 取得先（VIX）

| 項目 | 内容 |
|---|---|
| 取得先 | Cboe 公式ページ「Historical Data for Cboe VIX® Index」（https://www.cboe.com/tradable_products/vix/vix_historical_data）の「VIX Index data for 1990 to present (Updated Daily)」のリンク `https://cdn-api.cboe.com/api/global/us_indices/daily_prices/VIX_History.csv` |
| 形式 | 1行目 `DATE,OPEN,HIGH,LOW,CLOSE`、日付 `MM/DD/YYYY`、値は小数6桁、古い日付が先頭、休場日の行は無い（2026-10-30 に先頭の行で確認）。`CLOSE` を使う |
| FRED は使わない | 一次の Cboe から直接取る（FRED の VIXCLS も出どころは Cboe）。日米2年金利（`rates/`）と同じく、FRED の規約に自動取得の禁止の文があり位置づけを確認できていないため |
| 想定外の形 | 見出しに `DATE`・`CLOSE` が無い、日付・値の形が違う、値が0以下・200以上、列の数が違う、日付の重複 → 黙って捨てず失敗にする。ただし**末尾400行より古い行**（順位にも履歴にも使わない）の不備は、その行を飛ばして警告に記録する（1990年代の行の不備で毎日の更新が止まらないように） |

## 3. VIX 順位の定義

- **順位（%）＝ 当日を含む直近252営業日の終値のうち、当日の終値以下だった日の数 ÷ 252 × 100**（小数第1位に四捨五入）。
  - 252営業日はおよそ1年。同じ値は「以下」に数える。当日の値がこの1年で最も高ければ 100.0、最も低ければ 0.4（自分だけ）。
  - 個数×1000÷252 の端数がちょうど 0.5 になる個数は無い（0〜252の全数で確認、試験あり）ので、四捨五入の方式による違いは出ない。
- 止める基準は **70%以上**（swing-flow `SPEC.md` 3-6 の値。`risk/config.js` の `VIX.thresholdPct` は写し。記事の判定は swing-flow 側）。
- `risk.json` には、最新日の順位のほか、**直近60営業日の日ごとの順位**（`vix.history`）を残す。GPT の過去の値との照合に使う（9節）。
- 順位の範囲（252営業日）の中に、NYSE の営業日なのに行が無い日、休場日なのに行がある日があれば、警告に記録する（止めはしない）。

## 4. 鮮度・時刻（VIX）

- VIX の終値は米東部の16:15に確定する。CSV がいつ更新されるかは未確認のため、**米東部18:00を過ぎたら、その日の値があるはず**とみなして取りに行く（`READY_ET_MIN`）。最初の実運用で `Last-Modified` を記録し、実際の時刻を確かめる。
- 期待する最新日：米東部の現地時刻で18:00を過ぎていればその日、前なら前日から数え、NYSE の休場日を飛ばした日。日本時間では、夏時間は7:00、冬時間は8:00を過ぎると前の米国営業日の値を期待する。
- 営業日：NYSE の規則（`risk/lib/calendar.js`。2026〜2028年の公式発表〔NYSE Group、2025-12-23〕と一致することを試験で確認）。コロンブス・デー、退役軍人の日は開いている（債券市場の規則の `rates/lib/calendar.js` とは別）。規則で決まらない休場（国の追悼の日など）は `config.js` の `EXTRA_CLOSED_DATES` に足す。
- 状態（`--check-fresh`）：期待する最新日まで入っていれば **OK**、入っていないが掲載のはずの時刻から16時間以内なら **PENDING**（赤にしない）、それを過ぎたら **STALE**（赤）。
- 取得に失敗したとき：VIX は前回の値のまま残し、失敗を `generation.errors` に書く（イベント警戒は更新する）。終了コード1（実行は赤）。

## 5. イベント警戒の定義

### 5-1. 決め方（2026-10-30 ユーザー決定）

**基準時刻（日本時間のその日の9:00）から7日以内（168時間。9:00ちょうどは含み、7日後の9:00ちょうどは含まない）に発表される最重要の予定が、2件以上なら `High`、それ未満なら `Normal`。**

- 計算する時刻が9:00より前でも、基準はその日の9:00（例：FOMC の声明は日本時間の早朝3:00〜4:00なので、その日の記事の時点では発表済みとして数えない）。
- 予定表が窓の終わりまで届いていないとき：すでに2件以上あれば `High`（確定）、それ未満なら `unknown`（`reason` に理由）。
- 値は swing-flow の `risk: EVENT level=` が受け付ける `High`／`Normal`／`unknown` のどれか。
- 選ばなかった案（参考、2026年の平日259日での `High` の割合の概算）：「当日か翌営業日に1件以上」約38%、「14日以内に1件以上」約87%。採用した案は 38%（259日中99日。各日の10:00に計算した場合）。

### 5-2. 最重要の予定（`risk/events.csv`）

| kind | 予定 | 時刻（現地） | 公式の確認先 |
|---|---|---|---|
| FOMC | 米連邦公開市場委員会の声明（会合2日目） | 14:00 米東部（声明の発表文「For release at 2:00 p.m. EDT」による） | federalreserve.gov FOMC calendars |
| ECB | ECB理事会の金融政策の決定 | 14:15 フランクフルト | ecb.europa.eu |
| BOJ | 日銀 金融政策決定会合の最終日 | 記載なし（会合終了後） | boj.or.jp |
| BOE | 英中銀 MPC の発表日 | 記載なし（日程ページに時刻が無い） | bankofengland.co.uk |
| RBA | 豪中銀 金融政策委員会の決定 | 14:30 シドニー | rba.gov.au |
| BOC | カナダ中銀の政策金利の発表 | 9:45 米東部 | bankofcanada.ca |
| NFP | 米雇用統計 | 8:30 米東部 | bls.gov |
| CPI | 米消費者物価指数 | 8:30 米東部 | bls.gov |

- 2026年・2027年の全144件（中央銀行は各年8回、米統計は各年12回）。日付はすべて発表元の公式サイトで確認した（2026-10-30）。各 URL はファイルの先頭の注記に書いてある。
- 2026年1月分の米雇用統計・CPI は、予算失効による変更後の日付（2/11・2/13）。
- FOMC の2027年の日付は、FRB のページの注記どおり「直前の会合で確定するまでは暫定」。
- 時刻の記載が無い予定（日銀・英中銀）は、現地の正午とみなす。窓は日本時間の9:00で区切るため、日本・欧州の日中の発表なら、正午とみなしても数え方は変わらない。
- 想定外の行（種類・時間帯の違い・日付・時刻の形・重複・見出し）は、行番号つきで失敗にする。種類ごとの時間帯は `config.js` の `EVENT.kinds` で決めてあり、表の `tz` 列と違えば失敗。
- **予定表の終わり**：種類ごとの最後の予定のうち、いちばん早いもの（いまは 2027-12-03 の米雇用統計＝日本時間 22:30）。それより先は、まだ載っていない予定がありうる。終わりまで60日を切ったら警告を出す（毎年、各公式サイトの翌年の日程で更新する）。
- 日程が変わったとき（米政府機関の閉鎖で統計が延期された等）は、この表を直す。月曜の記事で週の予定を公式に確かめるときに、表と食い違いがないかも見る。
- 表に無い予定（英国の予算案、選挙など）は数えない。数えるかどうかは、決め方の変更として相談して決める。

### 5-3. 日本時間への変換

現地の日付・時刻・時間帯（IANA名）から、時間帯データベースに従って日本時間に直す（夏時間の切り替えを含む）。試験で、米・欧・英・豪の夏時間・冬時間のそれぞれで確かめている（例：FOMC 2026-10-28 → 日本時間 10/29 3:00、2026-12-09 → 12/10 4:00）。

### 5-4. 鮮度（イベント警戒）

`risk.json` の `event.base_jst` が「いま」の日本時間の日の 9:00 でなければ STALE。予定表は手元のファイルなので、`--if-stale` でも外部へは接続せずに数え直す。

## 6. 出典・利用条件

- VIX：Cboe「VIX Index Historical Data」。ページの注記は「furnished without responsibility for accuracy」。**Cboe の「Use of Cboe Content」（https://www.cboe.com/use-of-content）には「Cboe のロゴ・データ・画像などを使う前に Cboe の事前承認が必要」とある。公開記事に順位（派生した値）を載せることが該当するかは、確認できていない。** いまの記事も（友人資料経由で）同じ VIX の順位を載せており、同じ論点がある。記事を自前の値に切り替える前に、扱いを決める（9節）。
- 予定：各発表元の公式日程。
- `risk.json` の `citations` に出典の文を持つ。

## 7. `data/risk.json` の形（`schema: fxdaily-levels/risk/v1`）

| キー | 内容 |
|---|---|
| `as_of` | 作った時刻（日本時間） |
| `vix.date` / `close` | 最新の米国営業日と終値（小数2桁） |
| `vix.rank_pct` / `count_le` / `window` / `window_start` | 順位（%）、当日以下の日数、252、範囲の最初の日 |
| `vix.threshold_pct` / `over_threshold` | 70、基準以上か |
| `vix.warnings` | VIX の取得時の警告（穴・飛ばした古い行など） |
| `vix.source` | 取得先 URL、`last_modified`、`fetched_at` |
| `vix.history` | 直近60営業日の `{date, close, rank_pct}` |
| `event.level` | `High`／`Normal`／`unknown` |
| `event.base_jst` / `window_end_jst` | 窓の始まりと終わり |
| `event.count` / `high_count` / `items` | 窓の中の件数、2、予定の一覧（日本時間・種類・名前・現地の日時） |
| `event.calendar` | 予定表の終わり、ファイルの SHA-256、行数 |
| `event.reason` / `warnings` | `unknown` の理由、予定表の終わりが近い等の警告 |
| `generation` | `status`（ok／warning／error）、`errors`、`warnings`、`run_url` |
| `citations` / `notes` | 出典、定義の要約 |

内容が前回と同じ（`as_of`・取得時刻・`run_url` だけの違い）なら書き換えず、コミットも作らない。

## 8. ワークフロー

- `.github/workflows/risk.yml`（name: Risk Metrics）：日本時間の月〜土 7:10〜10:40（30分ごと）と、`Intraday Snapshot`・`Daily FX Data` の完了のたび（`workflow_run`）に `--if-stale` で起動。VIX が最新でイベント警戒も今日の分なら、外部へ接続せず数秒で終わる。書くのは `data/risk.json` だけ。取得に失敗しても、コミットと鮮度の確認（`--check-fresh`）は動かす。
- `.github/workflows/risk-tests.yml`：PR と main への push で試験（外部へは接続しない）。PR のときだけ、参考として Cboe の実データを取得して順位を表示する（`live-check`。リポジトリには書かない。失敗しても PR は止めない）。

## 9. GPT の値との照合と切り替え

1. VIX：swing-flow の `samples/` に残っている GPT の値（2026-09-18〜10-29 の約25日分、`risk: VIX rank=… date=…`）と、`vix.history` の同じ日付の順位を比べる。差があれば原因（取得先の違い・日付の扱い）を調べて報告する。
2. イベント警戒：GPT の値は 9/22 以降すべて High（友人の定義）。自前の定義では週によって Normal になる（例：2026-11-09〜11-27 は Normal）。**記事の取引量が変わる**ため、切り替える日はユーザーが決める。
3. 切り替えの前に決めること：Cboe の利用条件の扱い（6節）、記事の出典の書き方。
4. 残りの3項目（MOVE・HY OAS・中立の数）を自前で作るまでは、GPT への依頼は続ける。
